A — Right-Side Drawer
Inspired by Linear, Stripe, PatternFly, Adobe Commerce

Strengths

  • Page context stays visible — receptionist sees queue while adding
  • Natural scanning: queue on left, form on right
  • 460px width gives fields room without feeling cramped
  • Sticky footer with submit + keyboard hints
  • Standard SaaS pattern — zero learning curve
  • Scales well: add more fields without redesigning

Trade-offs

  • Partially obscures queue rows on narrow screens (<1200px)
  • Doctor cards not fully visible when drawer is open
  • More animation/transition logic to implement
Best for: Reception desks using 1280px+ screens. The dominant pattern for "add entity" forms in modern SaaS.

B — Centered Compact Modal
Inspired by Cal.com, Notion, Figma. Uses infield top-aligned labels.

Strengths

  • Maximum focus — blocks distractions, forces completion
  • Compact 2-column grid fits everything without scrolling
  • Infield labels save vertical space while staying visible
  • Works equally well on 1024px and 1920px screens
  • Simpler implementation (no drawer animation/resize logic)

Trade-offs

  • Fully blocks the queue view — can't glance at waiting patients
  • Infield labels slightly less accessible than top-aligned
  • Feels more "interrupting" than a drawer
  • Less room to grow if more fields are added later
Best for: Quick one-off additions where speed matters more than context. Good for clinics with a single receptionist.

C — Inline Expansion Card
Inspired by Doctolib, Google Calendar. Form expands in-page between sections.

Strengths

  • No overlay — full page context preserved at all times
  • 3-column grid puts everything on one row pair — ultra-compact
  • Feels like filling a card, not opening a dialog
  • Queue stays visible below — receptionist sees impact immediately
  • Fastest flow: focus field → type → tab → submit
  • No z-index/overlay complexity to manage

Trade-offs

  • Pushes queue down — may require scrolling on smaller screens
  • Compact layout can feel cramped with long names / many doctors
  • Notes field reduced to single-line (less room for details)
  • Doesn't scale well beyond 6-7 fields
  • Less conventional — some users may not recognize it as a form
Best for: High-throughput clinics where speed is critical and patients rarely need notes. Great for single-doctor practices.
