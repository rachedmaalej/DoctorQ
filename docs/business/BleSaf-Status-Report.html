The Problem & Solution
Why BleSaf Exists
In Tunisia, doctors assign patients a day, not a time. Patients arrive, sit, and wait — sometimes 1 to 3 hours — with zero visibility.

The Reality Today

  • Patients wait 1-3 hours with no idea when their turn is
  • Crowded, stressful waiting rooms create a negative experience
  • Some patients leave before being seen (revenue loss)
  • Receptionists manually manage chaotic queues
  • Doctors start consultations with already-frustrated patients
  • No data on wait times, no-shows, or daily throughput

With BleSaf

  • Patients scan a QR code or give their phone number
  • They see their real-time position and estimated wait
  • SMS alerts when it's almost their turn
  • Patients wait at a café, in their car, or at home
  • Receptionists manage the queue with one click
  • Daily analytics track throughput, wait times, and no-shows
Final Objective
Build a Scalable, Self-Service SaaS
A platform where any doctor in Tunisia can discover BleSaf, sign up without human contact, try it immediately, and convert to a paying customer — all on their own.
⚡

Frictionless Signup

A 3-field registration form (clinic name, email, password). No credit card required. Email verification, then straight into a guided onboarding. The goal: a doctor goes from "I just heard about this" to "I'm using it with patients" in under 5 minutes.

🎁

Try Before You Buy

Two possible models: a forever-free tier (up to 100 patients/month) that lets clinics use BleSaf indefinitely with basic features, or a 30-day full-access trial with all features unlocked. Either way, the doctor experiences full value before ever paying.

📈

Growth Engine

Every patient who receives an SMS becomes aware of BleSaf. Word-of-mouth between doctors. Low cost per clinic (50 TND/month). Break even at 10 clinics; target 50+ for a sustainable business. SMS credits as a scalable revenue add-on.

Technical Architecture
How It's Built
A monorepo with a React frontend, Node.js API, PostgreSQL database, and real-time WebSockets.

Frontend

React 18 + TypeScript + Vite
  • Tailwind CSS with RTL support
  • Zustand state management
  • Socket.io client (real-time)
  • react-i18next (French + Arabic)
  • React Hook Form + Zod validation
  • Code splitting with lazy loading
  • 14 pages, 30+ components

Backend API

Node.js + Express + TypeScript
  • JWT authentication
  • Socket.io server (real-time rooms)
  • Prisma ORM with PostgreSQL
  • Zod request validation
  • 45+ REST endpoints across 8 route files
  • 7 service modules (queue, stats, admin...)
  • Cron jobs (midnight reset, trial check)
  • Prometheus metrics endpoint

Recent Bug Fixes
Issues Resolved in This Session
Critical bugs discovered through testing and user reports, all fixed and verified.
Critical

Midnight Data Loss — Patient stats permanently deleted

The midnight scheduler used clearQueue() which permanently deleted all WAITING/NOTIFIED/IN_CONSULTATION entries without archiving. Days of patient data were silently destroyed. DailyStat model existed but was never written to.

Fix: New archiveAndClearQueue() function that (1) auto-completes IN_CONSULTATION patients, (2) snapshots stats to DailyStat, (3) only deletes WAITING/NOTIFIED. Admin dashboard now reads from DailyStat for historical charts.

Critical

Last-Patient Timing Distortion

The last patient of each day often stays IN_CONSULTATION because the receptionist forgets to close the queue. When auto-completed at midnight, their timing data is wildly inaccurate (e.g., 7-hour "consultation"), distorting all averages.

Fix: All time-based average calculations now exclude the last-called patient (latest calledAt) across statsService, queueService (DailyStat archival), and adminService (3 locations).

Major

Onboarding Infinite Loop

After completing 3 onboarding steps, the user was redirected back to step 1 instead of the dashboard. Root cause: auth store wasn't refreshed after the API call, so onboardingCompleted was still false.

Fix: Added await checkAuth() before navigate('/dashboard') to refresh clinic data in the store.

Major

CORS Error on Signup

Frontend running on port 5175 wasn't in the API's CORS whitelist. Signup requests were blocked by the browser.

Fix: Added port 5175 to CORS_ORIGIN environment variable.

Minor

Missing "Back" Translation

Settings page showed raw key common.back instead of translated text.

Fix: Added "back": "Retour" (FR) and "back": "رجوع" (AR) to locale files.
