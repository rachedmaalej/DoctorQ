Email Verification: The Smart Way

Allow immediate access, verify when it matters

❌ Current Approach

Block everything until verified

  • User signs up
  • Must check email
  • Click verification link
  • Only then can access dashboard

Problem: 20-30% never complete verification

✓ Recommended Approach

Verify when it matters

  • User signs up → Immediate dashboard access
  • Can explore, add patients, see QR code
  • Verify email required only for:
    • Sending SMS (consumes credits)
    • Upgrading to paid plan

Benefit: Users experience value before friction

Implementation Code

// In queueService.ts - when sending SMS
if (!clinic.emailVerified) {
  throw new Error('Please verify your email to send SMS notifications');
}

// Show gentle reminder in dashboard
{!emailVerified && (
  <Banner type="info">
    Verify your email to enable SMS notifications
  </Banner>
)}

Trial Email Strategy

Behavior-triggered emails increase conversion by 30%+

Day Trigger Email Goal
Day 0 Signup completed Welcome + Quick Start Guide Set expectations, link to dashboard
Day 1 No patients added "Add your first patient in 30 seconds" Activation nudge

Day 7 Time-based "How's it going?" + Tips Check-in, offer help

Day 23 7 days left "Your trial ends in 7 days" Urgency, upgrade CTA

Implementation Priorities

What to do before launch, and what can wait

🚨 Critical (Before Launch)

  • Create /verify-email page
    Frontend page to handle email verification links
  • Create /reset-password page
    Frontend page for password reset flow
  • Configure Resend API
    Required for any email to be sent
  • Configure Konnect API
    Required for payments to work
  • End-to-end flow test
    Signup → Dashboard → Add patient → Payment

⚡ High Impact (Week 1-2)

  • Implement delayed verification
    +15-25% activation improvement
  • Reduce signup to 3 fields
    +21% signup completion
  • Add "Test as patient" button
    Faster "aha moment"
  • Improve empty dashboard state
    Clear CTAs for new users
  • Add Sentry error monitoring
    Catch issues before users report them

📋 Nice to Have (Post-Launch)

Trial reminder emails • In-app tooltips • Analytics tracking • A/B testing • Demo mode • Video tutorials

Risk Mitigation

Anticipate problems before they happen

Risk Mitigation Strategy How to Monitor
Low signup conversion A/B test signup fields, simplify form, add social proof Track funnel drop-off at each step
High early churn Improve onboarding, add contextual tooltips, proactive support 7-day retention cohorts
Payment failures Offer manual bank transfer as fallback, retry failed payments Failed payment rate, abandonment
Support overload Comprehensive FAQ, WhatsApp quick replies, video tutorials Support ticket volume, response time
SMS cost overruns Low balance warnings (10 credits), hard limits, clear pricing SMS usage per clinic, negative balance attempts
Technical issues Sentry error monitoring, health checks, alerts Error rate, uptime, response times
